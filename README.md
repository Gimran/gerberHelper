# Allegro → Altium

Помощник для переноса платы из выгрузки Cadence Allegro в Altium через CAMtastic.
Эталон всегда производственные данные: всё, что утилита правит, она берёт из исходных
Gerber и файлов сверловки.

## Запуск

`Allegro-Altium.pyw` — двойной клик из проводника. Расширение `.pyw` связано с
`C:\Windows\pyw.exe`, лаунчером Python: он работает без консоли и сам находит
интерпретатор, поэтому путь к Python нигде не зашит. Для ярлыка: правый клик →
«Отправить» → «Рабочий стол (создать ярлык)».

`allegro2altium.bat` — запасной вариант с диагностикой: ищет Python, проверяет
`customtkinter` и, если чего-то не хватает, пишет что именно. Нужен, когда окно не
открывается и непонятно почему.

```
python cli.py info                 что найдено в папке
python cli.py run --all            анализ, ничего не пишет
python cli.py run --all --apply    с записью
python cli.py run drill            только конвертация сверловки
```

Нужен Python 3.10+ и `customtkinter` (только для окна): `pip install customtkinter`.

## Как это ложится на работу

**Вкладка «1. Сверловка» — до импорта.** CAMtastic не понимает сверловку Allegro.
Утилита переписывает `.drl` в Excellon, который открывается: единицы и координаты не
пересчитываются, повторы `Rnn` разворачиваются в явные отверстия, инструменты делятся
на металлизированные и нет. Понимает оба варианта выгрузки Allegro — с `M00` и с `Tnn`.
Дальше обычный маршрут: добавить `.TXT` в CAMtastic, расставить слои и пары сверловки,
извлечь нетлист, экспортировать в PCB.

**Вкладка «2. Плата» — после импорта.** Экспорт из CAMtastic кривой, причём по-разному
от платы к плате, поэтому операции включаются выборочно:

| Операция | Что делает |
|---|---|
| Растащить via по слоям | `STARTLAYER` / `ENDLAYER` по парам слоёв из имён файлов сверловки (`...-1-4.drl` → TOP..MID3). CAMtastic делает все переходные сквозными |
| Форма и поворот площадок | `SHAPE`, `XSIZE`, `YSIZE`, `ROTATION` по апертурам Gerber. Чинит повёрнутые апертуры (`%AM` с примитивом 21), которые CAMtastic превращает в прямоугольник без поворота |
| Диаметры via по слоям | Для Full Stack (`PADMODE=2`) — послойные размеры, `DIAMETER` ставится равным максимуму, как это делает сам Altium. По умолчанию выключено: диаметры обычно проще назначить одинаковыми руками |
| Полигоны без сети | Удаляет polygon pour без сети на медных слоях, с перенумерацией полигонов и ссылок `Region → Polygon`. Шелкографию не трогает |

То, что правится в Altium в пару кликов (например, массовое превращение падов обратно в
via), утилита не делает — это быстрее сделать массовым выделением.

**Вкладка «Слои».** Именование слоёв в Gerber — лотерея. Автоопределение читает запись
`G04 Layer: ETCH/<имя>`, а если её нет, смотрит на имя файла; маски лежат в
`layer_rules.json` рядом с утилитой и правятся без правки кода. Что автоопределение не
опознало или опознало неверно, назначается вручную выпадающим списком; выбор запоминается
для этой папки в `settings.json`. Глубина стека берётся из пар сверловки, при
необходимости задаётся руками.

## Как это устроено

- **Ничего не пишется без «Применить»** (в CLI — без `--apply`). Анализ считает всё и
  показывает отчёт.
- **Перед записью делается копия** `имя.PcbDoc.bakN`, номер растёт, старые копии не
  затираются.
- **Правятся только нужные поля.** Файл разбирается на записи и разделители строк, меняются
  значения внутри строк, поэтому порядок записей, CR-концы и все остальные байты сохраняются.
- **Проверка целостности.** После операций сверяется число записей каждого типа: измениться
  может только то, что удаляется намеренно. Висячие ссылки на удалённые полигоны отменяют запись.
- **Повторный прогон даёт ноль правок** — все операции идемпотентны.

## Порядок работы

Утилита приводит плату к Gerber, поэтому ручные правки вносятся после её прогона, а не до.
Если прогнать её повторно по уже доведённой плате, свои изменения она вернёт к тому, что
нарисовано в Gerber, и напишет об этом в отчёте.

## Требования к данным

- PcbDoc должен быть в текстовом виде: в Altium `File → Save As → PCB ASCII`. Двоичный файл
  утилита не читает.
- Altium с этим файлом на момент записи должен быть закрыт.
- Формат сверловки берётся из `nc_param.txt`, из заголовка `M48` самого файла или из
  `;FILE_FORMAT`. Если ничего нет, принимается 2:5 дюймы.

## Что остаётся человеку

- Площадки со сложными апертурами (`%AM` с примитивом 4, полигональный контур) не трогаются,
  они перечисляются в отчёте.
- Слои внутри пролёта via, где в Gerber площадки нет (подавленные неиспользуемые пады), по
  умолчанию остаются как есть. Галочка «обнулять» ставит туда 0, но как Altium отнесётся к
  нулевому пояску в DRC, надо проверять.
- Via, стоящая не точно на своём отверстии, отмечается в отчёте.

## Проверка

```
python tests/regression.py
```

Прогоняет утилиту на двух платах и сверяет результат с эталонами побайтово: конвертация
сверловки для обоих вариантов выгрузки Allegro и полный набор операций над PcbDoc.
Эталоны — файлы, полученные предыдущим набором отдельных скриптов.

Реальные платы, на которых это гоняется, в репозиторий не входят (`tests/fixtures/` в
`.gitignore`). Без них случаи из `tests/cases.json` помечаются как пропущенные, а не
проваленные. Чтобы проверять на своих данных, положите туда свои выгрузки по образцу
из `cases.json`: папка с `.drl` и `nc_param.txt` плюс папка `expected/` с ожидаемыми `.TXT`.

tests/                регрессия с эталонами обеих плат
