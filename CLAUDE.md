# gerberHelper: контекст для Claude Code

Помощник для переноса платы из Cadence Allegro в Altium через CAMtastic: готовит
сверловку до импорта и чинит ASCII PcbDoc после экспорта. Описание, команды и таблица
операций в `README.md`, здесь только то, что оттуда не видно.

## Как пользователь работает

Папка с Gerber и сверловкой, импорт в CAMtastic, экспорт в PCB, дальше в Altium
`Save As → PCB ASCII` и прогон утилиты по этой копии выборочно, смотря насколько кривой
экспорт. Via, пришедшие падами, возвращаются в via массовым выделением в самом Altium, и
диаметры via пользователь обычно выравнивает руками. Ручные правки вносятся **после**
утилиты, поэтому механизма исключений нет и не нужен (предлагали, отклонено).

## Решения, принятые по ходу

- Единицы и значения сверловки не пересчитываются, только структура файла.
- `DIAMETER` у Full Stack via равен максимуму по слоям (так делает сам Altium),
  диаметры по умолчанию выключены.
- Слои определяются масками из `layer_rules.json` (вынесены в JSON по просьбе
  пользователя) плюс ручное назначение; имена слоёв в Gerber непредсказуемы.
- Штриховка треками в полигоны: группа считается штриховкой при перекрытии 1.4 и выше
  (у дорожек около 1.0), значимые дыры сохраняются разрезом, потому что `Polygon` хранит
  один внешний контур.
- Шелкография: полигоны переписываются в `Region`, потому что полигоны тормозят Repour.
  Внутренние контуры `Region` пишутся в 1/10000 mil (проверено в Altium, в mil
  отображается неверно). Это единственный подтверждённый формат.
- Недостающие отверстия добавляются падами без цепи размером с отверстие, крупные можно
  делать неметаллизированными.
- Операции с `shapely` (штриховка, шелкография) подключают её лениво: ядро и CLI работают
  на стандартной библиотеке.

## Правила работы с этим репозиторием

- **Репозиторий публичный. Реальных плат, путей к проектам пользователя и названий его
  изделий в коммитах быть не должно.** `tests/fixtures/`, `settings.json`, `*.PcbDoc`,
  `*.Cam`, `*.bak*` в `.gitignore`. Снимки окна для README делаются только на
  синтетической демо-плате с нейтральными путями.
- Перед публикацией проверять файлы поиском по имени проекта и пользователя.
- Для коммитов в этом репозитории стоит noreply-адрес GitHub, не личная почта.
- Любая запись в файл платы делает копию `.bakN` рядом, старые копии не затираются.
  Altium с файлом должен быть закрыт, поэтому результат разумно писать в копию рядом.
- Проверка на реальной плате делается на копии, оригинал не трогать.

## Технические ловушки

- **PcbDoc правится токенами:** запись и разделитель строки. Меняются значения внутри
  строк, остальные байты остаются прежними, поэтому регрессия сравнивает файлы побайтово.
  Операции, добавляющие записи (`insert_after`), сдвигают позиции: **сначала удалять,
  потом вставлять**, и пересчитывать индексы.
- Нумерация (`INDEXFORSAVE`, `ID`, ссылки `POLYGON=`) должна оставаться сплошной.
  Удаление полигонов только через `PcbDoc.delete_polygons`.
- В Gerber расширенные команды `%...%` вырезаются до разбиения по `*`: иначе первый выбор
  апертуры после заголовка теряется.
- `allegro2altium.bat` записан в **cp866 с CRLF** (`chcp 866`). В UTF-8 `cmd` ломает метки.
  Окончания строк закреплены в `.gitattributes`.
- Длинные heredoc с кавычками в Bash этой среды ломаются: большие правки лучше делать
  файлом-скриптом.
- Формат ASCII PcbDoc: `Region` записан без ведущего `|`, `NAME` у полигонов кодами
  символов, координаты в `mil`, у заливки в 1/10000 mil.

## Проверка

```bash
python tests/regression.py   # реальные платы, пропускается без фикстур
python tests/test_hatch.py   # синтетические, нужна shapely
python tests/test_holes.py
python tests/test_silk.py
```

Все должны проходить. Регрессия побайтово сравнивает результат с эталонами; если она
краснеет после рефакторинга, поведение изменилось.
